# be-DailyJob 

> 이 회고는 작업량을 보고하기 위한 문서가 아니라, 
> 오늘 내가 어떤 판단을 했고 어떤 개발 행동을 반복하거나 바꿔야 하는지 확인하기 위한 기록입니다. 
> 각 항목은 길게 쓰기보다, 사실/판단/근거/다음 행동이 드러나게 구체적으로 작성하세요.

### 1. 오늘 완료한 것
- 오늘 실제로 끝낸 기능/수정/학습:
  - 라이더 위치를 redis에 저장 기능 구현.
  - 라이더 위치 검증 기능 구현
- (오늘의 목표 중에서) 아직 끝내지 못한 부분:
  - redis pub/sub을 이용한 sse 구독 기능
### 2. 오늘 가장 의미있었던 기술적 판단
- 내가 내린 판단:
  - 추후 스케일 아웃을 염두해 두었을 때, redis pub/sub으로 전환
- 그렇게 판단한 이유:
  - 이미 Redis 인프라를 사용하고 있어서 별도의 인프라 공수가 들지 않았음.
  - SSE 를 연결하는 기능은 아직 구현이 안되어 있어 pub/sub으로의 전환 비용이 적음.
- 고려했지만 선택하지 않은 대안:
  - 서버 내부 polling과 kafka 를 생각 했지만 따로 인스턴스를 띄우거나 로직이 복잡해지는 등의 문제가 있음.
- 이 판단이 코드 품질/테스트/유지보수에 미친 영향:
  - 오히려 아무 변동사항이 없다.

### 4. 오늘 잘한 행동(개발과 관련된 것)
- 어떤 행동이었는지:
  - 이슈를 쪼개어 개발함.
- 그 접근이 도움이 된 이유:
  - 큰 이슈 하나를 그대로 구현을 AI 에게 시키면 반드시 검증 과정에서 문제가 발생할 것이라고 생각.
  - /plan으로 먼저 계획한 후에 서브 이슈로 나누어 구현하게 명령.
- 다음에도 반복하고 싶은 점:
  - 첫 mvp 구현인 만큼 쪼개어 구현하는 것.
